# WanHap — переход hAP ac lite на основной WAN-шлюз

Дата создания: 2026-09-28  
Последнее уточнение: 2026-09-29 — текущий DNS на TP-Link задан через GeoHide DNS  
Статус: **NOT_STARTED**

## Цель

Перевести MikroTik hAP ac lite в основной маршрутизатор дома:

```
Интернет / ISP
      ↓
   hAP WAN
      ↓
  LAN + Wi-Fi
  sweethomeu
      ↓
  клиенты
      ↓
 DIRECT / Zapret2
```

TP-Link после перехода не должен быть обязательным маршрутизатором для домашней сети.

## Временная схема

На переходном этапе TP-Link остаётся источником Интернета для hAP, но уже **по Ethernet**:

```
TP-Link LAN
     ↓ Ethernet
hAP WAN
     ↓
sweethomeu
```

Текущий Wi-Fi uplink hAP через `phy0-sta0` используется только как временный rollback-путь до подтверждения проводного WAN.

## Текущий DNS baseline

По уточнению пользователя, **на TP-Link сейчас заданы DNS от сервиса GeoHide DNS**:

```
https://dns.geohide.ru:8443/
```

Это является частью текущего TP-Link baseline и должно быть сохранено как факт исходной схемы.

### Важное правило миграции DNS

DNS GeoHide на TP-Link **не считать автоматически перенесённым на hAP**.

При переходе:

```
TP-Link → Ethernet → hAP
```

hAP может использовать свою собственную DNS-конфигурацию, поэтому:

- не менять DNS одновременно с первым переключением WAN;
- сначала зафиксировать текущую DNS-конфигурацию hAP;
- отдельно определить целевую DNS-схему для hAP;
- только после этого, отдельным контролируемым шагом, менять DNS при необходимости;
- не считать сам факт работы GeoHide на TP-Link доказательством того, что тот же DNS уже используется клиентами за hAP.

Пока отдельное решение по переносу GeoHide на hAP не принято, **не заменять текущий hAP DNS автоматически**.

Официальная страница статуса GeoHide DNS в настоящее время показывает несколько рабочих серверов, поэтому в плане не фиксируется один конкретный IP как единственный адрес сервиса. citeturn837837search0

## Правила

- Zapret2 / Deep Max Circular не перестраивать в рамках этого плана.
- Не менять одновременно WAN, LAN, DNS, Wi-Fi и Zapret2.
- Каждый этап должен закончиться статусом **DONE** до перехода к следующему.
- При проблеме вернуть предыдущий WAN-путь; текущая рабочая конфигурация Zapret2 должна остаться нетронутой.
- DNS GeoHide на TP-Link сохранять неизменным до отдельного решения по DNS.
- Не выполнять лишнюю диагностику: только проверки, необходимые для перехода и подтверждения работоспособности.

## Этапы

### W0 — Зафиксировать текущий WAN + DNS baseline
**STATUS: NOT_STARTED**

Только чтение текущей сетевой конфигурации hAP:
- какой интерфейс является WAN;
- как сейчас работает `phy0-sta0`;
- какие LAN/DHCP/Wi-Fi настройки уже используются;
- какая DNS-схема фактически используется самим hAP;
- какие DNS-настройки являются текущим baseline на стороне TP-Link.

Изменений нет.

### W1 — Поднять временный проводной WAN через TP-Link
**STATUS: NOT_STARTED**

Подключить:

```
TP-Link LAN → Ethernet → hAP WAN
```

Настроить hAP WAN на получение Интернета от TP-Link.

DNS на TP-Link **не менять**.

Критерий DONE:
- hAP получает WAN;
- с самого hAP есть Интернет;
- текущий Wi-Fi uplink ещё не удалён и остаётся rollback-путём;
- текущая DNS-конфигурация TP-Link не изменена.

### W2 — Переключить hAP с Wi-Fi uplink на Ethernet WAN
**STATUS: NOT_STARTED**

После подтверждения W1 сделать Ethernet WAN основным и отключить только старый Wi-Fi uplink `phy0-sta0`.

DNS не менять в рамках этого этапа.

Критерий DONE:
- Интернет hAP идёт через WAN Ethernet;
- LAN/Wi-Fi клиентов hAP работают;
- Zapret2 остаётся запущенным;
- rollback на предыдущий uplink возможен;
- DNS baseline TP-Link сохранён.

### W3 — Сделать hAP единственным домашним шлюзом
**STATUS: NOT_STARTED**

Сохранить/перенести на hAP основную домашнюю сеть:

- SSID: `sweethomeu`;
- DHCP/DNS/NAT — на hAP;
- обычный трафик → DIRECT;
- проблемный трафик → существующий Zapret2.

TP-Link на этом этапе всё ещё можно оставить подключённым как резервный/временный источник, но он больше не является шлюзом домашней сети.

### W3-DNS — Отдельно определить целевую DNS-схему hAP
**STATUS: NOT_STARTED**

Это отдельный DNS-gate, а не часть автоматической миграции WAN.

Варианты:
- сохранить текущий DNS hAP;
- перенести на hAP DNS GeoHide;
- использовать иную выбранную DNS-схему.

Никакой вариант не считается выбранным заранее.

Критерий DONE:
- целевая DNS-схема явно выбрана;
- её изменение выполнено отдельно от WAN-переключения;
- проверены DNS-запросы и обычный HTTPS;
- Zapret2 не менялся.

### W4 — Подключить настоящий ISP WAN напрямую к hAP
**STATUS: NOT_STARTED**

Перенести кабель Интернет-провайдера с TP-Link на физический WAN-порт hAP.

Тип WAN (DHCP / PPPoE / другой) определить по фактической схеме провайдера; не предполагать его заранее.

Целевая DNS-схема W3-DNS к этому моменту уже должна быть определена.

Критерий DONE:
- hAP самостоятельно получает Internet WAN от ISP;
- TP-Link больше не нужен как upstream.

### W5 — Вывести TP-Link из основной схемы
**STATUS: NOT_STARTED**

После успешного W4:
- TP-Link убрать из пути домашней сети;
- не менять без необходимости существующий LAN/SSID;
- сохранить hAP как единственный основной маршрутизатор.

Критерий DONE:

```
ISP → hAP → sweethomeu → клиенты
```

### W6 — Минимальная финальная проверка
**STATUS: NOT_STARTED**

Проверить только необходимое:

1. клиент получает IP/DNS от hAP;
2. выбранная целевая DNS-схема реально используется;
3. обычный HTTPS работает;
4. один представитель проблемного сервиса проходит через текущий Zapret2;
5. hAP переживает обычный restart без потери WAN/LAN/DNS;
6. rollback-конфигурация сохранена.

Без новых экспериментов со стратегиями.

## Rollback

До W4 исходный Wi-Fi uplink через TP-Link сохраняется как аварийный путь.

При неудаче проводного WAN:
1. вернуть предыдущий uplink;
2. вернуть предыдущую сетевую конфигурацию;
3. не трогать Deep Max Circular/Zapret2;
4. не менять DNS TP-Link.

## Финальное состояние

**TARGET:**

```
ISP
 ↓ Ethernet
hAP WAN
 ↓
hAP LAN / Wi-Fi
 ↓
sweethomeu
 ↓
клиенты
 ↓
DIRECT
или
Zapret2 для проблемных направлений
```

TP-Link: **не является частью основной маршрутизации**.

DNS: **отдельно выбранная и проверенная схема на hAP**; GeoHide остаётся исходным DNS baseline TP-Link до отдельного решения.
